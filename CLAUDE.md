# Cubing PB tracker

Jaden's 3x3 PB tracker. GitHub: jadenzou1-dotcom/cubing-pbs (public), branch `main`. Everything under `stats/`, `fast-solves/README.md` and the root `README.md` is generated by `python3 scripts/build.py`; never edit those by hand. Layout: one page per PB at `stats/<event>/<event>_<file stem>.md`; all images flat in `stats/charts/`. build.py deletes and recreates `stats/` on every run, so don't add folders or files there. The input format is documented at the top of `scripts/build.py`.

## Three docs, three jobs
- `README.md`: generated by build.py. Current PBs and PB history, for other cubers. Never edit by hand.
- `REPO_GUIDE.md`: overview of the repo, not touched by build.py (folders, what each chart and stat shows, the consistency metric). **Update it whenever you add a stat, chart, folder or file convention.**
- `CLAUDE.md`: this file. Workflow instructions for Claude (Claude Code loads it automatically).

## Workflow: user pastes a PB or solve in chat
1. Save it as a new file, never overwrite an old one:
   - PB: `records/<event>/YYYY-MM-DD.txt`, with `<event>` one of `single`, `ao5`, `ao12`, `ao25`, `ao50`, `ao100`.
   - Second PB of the same event on the same day: `YYYY-MM-DD_2.txt`, then `_3`, in the order they happened.
   - Good non-PB solve: `fast-solves/YYYY-MM-DD[_N].txt`, one solve per file. No distributions for these.
2. Paste the csTimer export as given (header lines are skipped). If it has an `avg of N:` or `single:` line, build.py warns when its computed value differs; resolve any warning before pushing.
3. Run `python3 scripts/build.py`, then `git add -A`, commit, and `git push`.
4. Use the date the user gives; if unclear, ask (csTimer stores real solve dates). Today's date is not necessarily the solve's date.

## Reconstructions
Optional. `>` lines directly under the numbered solve, one step per line with a `//` label:

```
> x' z // inspection
> R U x' D F L2 D2 // cross
> L' U L y U' L U L' // pair 1 (green-orange)
> (F R U R' U' S R U R' U' f') // OLL
> U (R' U' R U D' R2 U R' U R U' R U' R2 D) U2 // PLL (Gb)
```

- Labels build.py recognizes: inspection, cross / xcross / xxcross, pair / f2l / slot, OLL, PLL, AUF, and "skip".
- Algs go in brackets; AUFs go outside the brackets on the same line.

**The user dictates by voice, so primes and rotations are often wrong.** Verify every reconstruction before pushing:
- Open alg.cubing.net in the browser pane and run `import("https://cdn.cubing.net/v0/js/cubing/puzzles")`.
- Apply scramble + reconstruction to `cube3x3x3.kpuzzle()`'s default pattern.
- Check `experimentalIsSolved({ignorePuzzleOrientation: true, ignoreCenterOrientation: true})`.
- If it fails, check stage by stage (cross, then each pair, then OLL, then PLL) to find where it breaks and try prime variants. Tell the user what you changed.

## Preferences the user has stated
- No extra how-to or instruction sections in the generated READMEs; they send PBs through chat.
- No per-step tables in reconstructions; keep the one-line breakdown.
- README history columns: Date, Time, Improvement, σ, σ / mean, Stats. No Recon column.
- ao5 and ao12 use the number-line chart, ao25 and up the density curve (`Solves within a 1-second window`). Keep the per-second gridlines on time axes.
- Keep the fast-solve bank free of distributions and averages.
- The repo is public; don't commit anything personal beyond cubing data.
- Commit messages end with the `Co-Authored-By` line from the session's attribution instructions.
